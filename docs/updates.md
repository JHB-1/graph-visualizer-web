# 웹 자동 업데이트

빌드마다 update-manifest.json에 제품/버전과 공개 자산별 크기, SHA-256을 기록합니다.
같은 원본의 update-worker.js가 목록과 모든 파일을 검증한 뒤 버전별 CacheStorage에 준비합니다.
이전 버전과 준비 버전을 섞어 사용하지 않으며 설치 도중 오류가 나면 새 캐시만 버립니다.

열려 있는 문서를 강제로 새로고침하지 않습니다. 새 버전 안내의 그래프 저장으로 JSON을 출력하고,
모든 GV 탭을 닫은 뒤 다시 열면 대기 중인 워커가 전환됩니다.
브라우저 자동 저장을 켠 문서는 기존 복구 절차로 다시 열 수 있습니다.
자동 저장을 껐거나 브라우저가 저장을 차단하면 JSON 출력이 필요합니다.
자동 업데이트가 저장/Undo/카메라를 별도로 복제하거나 자동 저장 OFF를 무시하지 않습니다.

초기 로드와 보이는 동안 5분마다 확인합니다. 네트워크/저장소/검증 오류는 현재 문서를 유지합니다.
현재 버전과 직전 코드 캐시를 유지하며 다른 제품/경로의 캐시와 IndexedDB는 지우지 않습니다.
이미 실행 중인 JS를 갈아끼우는 기능은 아닙니다. 최초 지원 버전 전환은 새로고침이 필요합니다.

최대 자산 100개/총 32 MiB, 알려진 상대 경로만 허용합니다.
HTTPS 같은 원본 신뢰와 파일 SHA-256을 사용하며 별도 서명/배포 계정 탈취 방어를 제공한다고 주장하지 않습니다.
로컬 개발의 localhost HTTP는 브라우저의 보안 컨텍스트 예외입니다.
MCP 위젯과 gv:// 로컬 앱에서는 이 웹 업데이터를 시작하지 않고 각 호스트가 갱신을 담당합니다.

검사: tests/update_test.py는 실제 WASM 문서의 변경을 유지한 채 새 버전을 대기시키고,
탭 종료 후 버전 전환/복구, 손상된 후속 업데이트 거절을 확인합니다.
